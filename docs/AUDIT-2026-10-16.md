# Firmware audit, 2026-10-16

Three read-only passes over the whole tree (core/power/UX; storage/network; audio/NFC/OTA/
prompts/WiFi) at 1.2.17. This file keeps the findings that matter and the plan; the
fault-code system that came out of it is docs/FAULTS.md. "Safe" = can be shipped to the one
field unit without a bench board (desk-reviewed logic, protected by OTA rollback).

## Findings that can hurt a device

1. **Frozen battery voltage.** When the gauge is present but its reads fail, the voltage
   smoothing buffer is refilled with the previous value while telemetry stays "valid", so the
   3.00 V cutoff can never fire (BatteryManagement.cpp refreshBatteryState / updateChargerMeasurements).
   The charger's own thermistor is ignored (`TS_IGNORE`), so temperature protection is also
   firmware-only on that same frozen data.
2. **Charger register race.** The poll task's read-modify-write of REG0F can turn charging
   back on while the loop suspended it for temperature; the supervisor then believes it is
   suspended. Needs the bus lock across the whole sequence.
3. **1 A into a sub-CUV cell.** Every dead-cell-recovery wake runs `begin()`, which applies the
   1000 mA default before the recovery hold drops it to 300 mA.
4. **OTA image confirmed without reaching the portal.** The image is confirmed after 60 s of
   uptime regardless of network; an image that boots but cannot reach the portal is kept.
5. **Prompt pack: a power loss between the two renames can leave no `/sounds` at all.**
6. **NFC UID buffer is 7 bytes; the library copies `uidLength` bytes.** A 10-byte UID tag
   overflows the stack.
7. **Silent failures.** SD mount, audio init, bring-up failure, decoder failures and most
   download failures reach neither the child, the LED nor the portal (fixed by FAULTS).

## Correctness bugs found

- `volumeBeep()` resets its own transient flag; the beep ends as if a story had, and advances
  the playlist (re-triggers the download wait).
- `String`s read across tasks without the audio lock (`getCurrentTrack`, `playlistContains`,
  `currentNFCData().uidString`, OTA `_error/_pendingStatus`): use-after-free risk.
- `playPrompt` writes its bookkeeping before taking the lock; `stop()` leaves prompt state.
- `queuedMask` in VoicePrompts is updated from the WiFi event task without atomics (a lost
  clear suppresses that prompt forever).
- Download give-up paths drop the queue entry without firing the completion callback: the
  figure tracker never completes and the playlist waits forever; a premature server close
  counts as a "hard" (size-mismatch) failure and permanently drops a file after 3.
- `saveDownloadQueue` runs per asset and per attempt (O(N²) card writes, inline SD on the loop
  when the maintenance queue overflows).
- Races: `activeEndpoint`/`jobStartedAt` read without `jobLock`; `cachedFreeBytes` (64-bit)
  across tasks; ring indices volatile not atomic; `finishRequested` check-then-set.
- Report `snprintf` overflow retried every loop pass (log spam); partial JSON escaping.
- Manifest loaders have no `.tmp` fallback (a crash between remove and rename loses a manifest).
- Diag `MAX_SECTIONS = 16` with 19 sections (three sections mis-attributed); `send` console
  command outside the else-if chain; unbounded `while(!Serial.available())` in `factory`/
  `poweroff` (trips the 120 s watchdog); `stack` command assumes a 16 KB stack.
- ReadAheadFileSource park handshake can close/seek a `File` the reader is still in.
- `isDeletePending` only consulted by the inventory: a file queued for deletion counts as
  present and can be announced for playback.
- `last_error` was one slot, last-writer-wins, cleared by unrelated successes, classified by
  substring matching of free-text errors.

## Structure

- main.cpp: 3,600 lines, ~1,600 of them the serial console (76 commands, bench tools shipped
  ungated: learning cycle, sleeptest, chargemon, speedtest, gaugebus release, `endpoint set`
  persisted in NVS). Charger supervisor, dead-cell recovery, bring-up, LED scene, prompt UX,
  network start all live in main.
- BatteryManagement.cpp: 2,800 lines mixing bit-banged I2C, two chip drivers, SOC estimation,
  provisioning, bench tooling and printers.
- FileManager / RequestManager / ReverbClient: responsibilities blur (RequestManager is HTTP
  client + content cache + inventory; ReverbClient hand-parses JSON with `strstr` and builds
  the report with `snprintf`); retry/backoff implemented four times; the manifest schema is
  walked five times; two TLS clients; token refresh implemented twice.
- Logging: main.cpp uses `ESP_LOG*`, everything else `Serial.printf` (no tags, no levels).
- Dead code: legacy `/figures` layout, `AsyncSpeedTest` (deletes its client inside its own
  callback), `get/post`, unused callbacks, stubs (`commit()`, NFC watchdog, QR print),
  Arduino PROV event cases that never fire.
- Build is `debug` / `-Og`.

working); bus lock across charger/gauge sequences; recovery-wake charge current; OTA

build flags; AudioController / BatteryManagement / RequestManager splits.
